# AGENTS.md

Hexlet learning project «Календарь звонков»: a call booking service. The scenario and requirements are in `README.md`.

## Commands

`mise.toml` pins tool versions and defines tasks and dev servers; run everything through mise.

- `mise install` — pinned tools, npm dependencies and Git hooks. A fresh clone needs `mise trust` first.
- `mise run check` — every check: lint, type check, tests. CI (`.github/workflows/check.yml`) runs this same task.
- `mise run lint` and `mise run fix` — hk steps from `hk.pkl` (oxlint, oxfmt, jactionlint); `fix` applies autofixes.
- `mise run typecheck`, `mise run test`, `mise run build`.
- One test: `npm test -w backend -- test/smoke.test.ts` or `npm test -w backend -- -t "<test name>"`.
- `mise daemons start`, `stop`, `status`, `logs` — backend and frontend dev servers. `mise daemons urls` shows the ports: 3000 and 5173 in the main checkout, other ports in each worktree.

## Structure

npm workspaces with one lockfile at the root.

- `backend/` — Fastify. `src/app.ts` builds the app and tests import it; `src/server.ts` only listens on `HOST` and `PORT`. Node runs TypeScript directly, so there is no build step: relative imports need the `.ts` extension and only erasable TypeScript syntax works.
- `frontend/` — Vite, React, Mantine.
- `compose.yaml` — dev Postgres. The app does not use it yet.

## Rules

- The API is contract-first: TypeSpec → OpenAPI → frontend SDK from `@hey-api/openapi-ts`. That generator fails on TypeScript 7, which the workspaces use; give the contract package its own `typescript@6`.
- `.github/workflows/hexlet-check.yml` is generated by Hexlet. Do not edit, delete or rename it, and do not rename the repository. It fails until all project steps are completed on Hexlet; that is expected.
- Each worktree gets its own Compose project and tools through hooks in `.claude/`. Triggers and manual cleanup: `docs/agents/worktrees.md`.

## Коммиты

Самостоятельно коммить завершённые изменения после проверок.
Используй Conventional Commits, в scope указывай компонент проекта.
Для работы по тикету добавляй его ключ в заголовок.
В описании объясняй причину изменения и новое поведение.
Включай в коммит только изменения своей задачи.
Формат заголовка проверяет хук `commit-msg`.
